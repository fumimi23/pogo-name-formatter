# pogo-name-formatter

ポケモンGOの個体値を入力すると、ポケモンに付けるニックネームを生成するツール。

**公開URL: https://fumimi23.github.io/pogo-name-formatter/**

スマホのブラウザで上記URLを開けばすぐに使える（GitHub Pages で公開）。

## 名前の形式

```
個体値の割合(小数第1位) 半角スペース 個体値16進数(攻撃→防御→HP)
```

- **個体値の割合**: `(攻撃 + 防御 + HP) / 45 * 100` を小数第1位で表示
  - ただし `100.0`(15/15/15) のときのみ、文字数節約のため `99.9` と表示する
- **個体値16進数**: 攻撃・防御・HP の各値(0〜15)を1桁の16進数(0〜F)で連結

### 例

| 攻撃 | 防御 | HP | 割合 | 16進数 | 名前 |
|----:|----:|---:|------|--------|------|
| 15 | 15 | 15 | 100.0→99.9 | FFF | `99.9 FFF` |
| 15 | 14 | 13 | 93.3 | FED | `93.3 FED` |
| 0 | 0 | 0 | 0.0 | 000 | `0.0 000` |

## 入力

攻撃 / 防御 / HP をそれぞれ 0〜15 で指定する。
（入力方式の参考: みんポケ「新・個体値ランクチェッカー」 https://9db.jp/pokemongo/data/6606 ）

### スクショから読み取る

鑑定画面のスクショを読み込み、攻撃 / 防御 / HP の各バーをタップすると、塗り（色つき）と空き（灰色）の比率から個体値を推定して自動入力する（`個体値 = 15 × 色つき ÷ (色つき + 灰色)`、白い区切りは除外）。検出した値は手入力UIに反映され、± で微調整できる。完全にクライアントサイドで動作しサーバー不要。端末・UI によっては外れることがあるため、推定後の確認・修正前提の補助機能。

## 動作環境

インストール不要の単体 HTML ファイル。外部リソース（CDN・フォント・通信）に一切依存しないため、`index.html` を直接ブラウザで開けばオフラインでも動作する。

公開先としては GitHub Pages（`main` ブランチのルート）を利用しており、上記の公開URLからアクセスできる。`index.html` を更新して `main` に取り込めば、自動的にサイトへ反映される。

PWA に対応しており、公開URLをスマホのブラウザで開いて「ホーム画面に追加」するとアプリのように起動できる。Service Worker（`sw.js`）がアプリシェルをキャッシュするため、一度開けばオフラインでも利用できる。

## 開発

Node のバージョンは `.node-version`（nodenv）で固定している。リンター/フォーマッターは導入していない（外部依存ゼロの構成を保つため）。

favicon はインライン SVG（自己完結）。OGP 画像（`assets/ogp.png`）は外部ツールを使わず標準ライブラリだけで生成しており、`python3 tools/gen-images.py` で再生成できる。

## テスト

テストは `index.html` から関数を抽出して実ソースを検証するため、単一ファイル構成は維持している。テストを仕様の台帳とみなし、3 層に分ける。

- `test/spec/`: 約束の台帳。ここにある挙動が仕様で、各テストに対応 issue 番号を併記する（名前生成ロジック `formatName` など）
- `test/unit/`: 実装都合のテスト。自由に変更・削除してよい（スクショ解析の純粋関数など）
- `test/invariants/`: システム全体を走査する横断不変条件

```sh
node --test          # JS のテスト（3 層すべて）
sh scripts/check.sh  # ローカル CI 一式
```

## ローカル CI

push 前に `.githooks/pre-push` が `scripts/check.sh` を実行し、失敗したら push を中止する。クローンごとに一度、次のコマンドで有効化する。

```sh
git config core.hooksPath .githooks
```

緊急時のみ `git push --no-verify` でスキップできる。GitHub Actions（`.github/workflows/ci.yml`）も push / Pull Request 時に同じ `scripts/check.sh` を実行する。

## issue 運用

- 1 issue = 1 セッションで進める。着手する issue は `python3 scripts/next-issue.py` で選ぶ
- issue には優先度ラベル `P0` / `P1` / `P2` を必ず 1 つ付ける。着手中は `in-progress` ラベルを付けてアサインする
- 他の issue 待ちのときは、本文に `Blocked by #N` 行を書く
- リリース単位はマイルストーン（マイルストーン名 = タグ名）。残りが 0 になったら `sh scripts/release.sh <タグ>` で版を切る
